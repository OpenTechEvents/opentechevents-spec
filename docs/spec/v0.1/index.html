event — OTE Event

  • specVersion const: "0.1.0" required

    Version of OTE Spec this document adheres to.

  • id string (uri) required

    Stable, globally unique identifier. A URI under a domain the publisher controls. Minted once, never rewritten — this is what lets consumers update an event instead of duplicating it.

  • url string (uri) optional

    Canonical URL where the event is described today. May change over time; id may not.

  • name string required

    Display name of the event.

  • description string optional

    Short description. Plain text or Markdown.

  • timezone string required

    IANA timezone (e.g. Europe/Madrid). Turns a wall-clock startDate into an unambiguous instant. For all-day events it contextualises the date — it does not shift it.

  • startDate string required

    Wall-clock start: a date (2026-10-15) for all-day events, or a local date-time (2026-10-15T09:00:00). Never carries a UTC offset — timezone does that.

  • endDate string optional

    Wall-clock end, in the SAME form as startDate (both dates, or both date-times). If absent, the event is assumed to end on the day it starts.

  • license string required

    License of THIS DATA, not of the event. SPDX identifier (CC0-1.0, CC-BY-4.0…) or a URL.

  • location object optional

    What is KNOWN about where the event happens. Not the same question as attendanceMode, which states the organiser's intent.

  • location.venue string optional

    Human-readable physical location. Its presence means the event has a physical venue.

  • location.onlineUrl string (uri) optional

    URL to attend online. Its presence means the event has online access.

  • attendanceMode enum: in-person | online | hybrid optional

    What the organiser says this event is. NO DEFAULT: absent means unknown, never in-person.

  • languages string[] optional

    BCP 47 tags, e.g. ["es","en"]. No default: absent means unknown.

  • status enum: scheduled | cancelled | postponed | rescheduled optional

    A cancelled or postponed event MUST stay published: removing it leaves a dead event in subscribers' calendars.

  • source object optional

    Provenance. Required when the event was imported or aggregated from elsewhere; omitted when the organiser describes their own event — they are the source.

  • source.name string required

    Name of the origin (e.g. "Rust Madrid", "Meetup").

  • source.url string (uri) optional

    Link to the original record, so the data can be verified and corrected upstream.

  • source.license string optional

    License under which the ORIGIN publishes the data. Constrains what may be republished: declaring a license does not grant rights the origin never gave.

  • source.retrievedAt string optional

    When the data was fetched.

feed — OTE Feed

  • specVersion const: "0.1.0" required

    Version of OTE Spec this feed adheres to. Applies to every event in it.

  • title string required

    Human-readable name of the feed.

  • description string optional

    Short description of the feed.

  • url string (uri) optional

    Canonical URL of the community, directory or organisation publishing the feed.

  • license string required

    License for the feed's contents. Acts as the DEFAULT for every event that does not declare its own. SPDX identifier or URL.

  • licenseUrl string (uri) optional

    URL of the full license text.

  • updatedAt string required

    When this feed was generated.

  • events object[] required

    Events in this feed. Each one inherits the feed's specVersion and license unless it declares its own.

Not generated from the schemas

The field you need isn't here

Add it. OTE's schemas do not forbid extra fields, on purpose: your document stays valid, and a consumer that doesn't understand them can ignore them safely. This is how the spec grows — through fields someone already uses, not fields we imagine will be needed.

Candidate for the core

A generic field that could become part of OTE. Write it without a prefix. If enough people need it, it gets standardised — and your local meaning gives way to the normative one.

"capacity": 80

Someone else's vocabulary

A field whose meaning is defined by another project, and that will never belong to OTE. Write it with a prefix. It cannot collide with a core field, today or at 1.0.

"combuilders:communityId": "gdg-madrid"

OTE will never mint a field name containing a colon. That reservation is what makes the second column safe — and what lets OTE connect to other specifications without being coupled to them.
